# AI Asset Generation & Local Asset Standards
<!-- id: assets.root -->

Purpose: Define how AI-generated imagery and other visual assets are created, stored, optimized, documented, referenced, and validated inside generated projects.

This module applies whenever imagery, illustration, icons, backgrounds, textures, diagrams, or other custom visual media materially improves the requested artifact.

---

# Local Asset Principle
<!-- id: assets.local-asset-principle -->

Production-intent projects SHOULD be self-contained.

When a required visual asset can be generated by the AI, generate it and place it inside the local project.

Do not leave the implementation dependent on temporary remote placeholder imagery.

---

# Asset Generation Trigger
<!-- id: assets.generation-trigger -->

Generate an asset when it materially improves:

- brand differentiation
- product explanation
- visual storytelling
- trust
- conversion
- onboarding
- empty states
- industry relevance
- editorial quality

Do not generate imagery merely to fill empty space.

---

# AI Generation Requirement
<!-- id: assets.ai-generation-requirement -->

When the execution environment provides an image-generation capability and custom imagery is appropriate, the AI SHOULD generate the required imagery as part of the creation workflow.

For key visual assets such as a hero image, branded illustration, product concept, or editorial image, prefer generation over leaving a placeholder.

If the requested creation explicitly requires custom images, generation becomes required when the capability exists.

---

# No Remote Placeholder Standard
<!-- id: assets.no-remote-placeholder -->

Production-intent output MUST NOT rely on:

- placeholder image services
- temporary stock-photo URLs
- random external CDN image URLs
- screenshots copied from unrelated products
- inaccessible local paths
- "replace this later" image blocks

Use local project assets.

---

# Proof-Bearing Media & Fidelity Standard
<!-- id: assets.proof-bearing-media -->

For categories where customers judge the business by visible real-world outcomes, environment, craft, property, product, food, venue, or physical service quality, the media strategy is part of the trust system.

Examples include landscaping, construction, home services, real estate, hospitality, restaurants, travel, automotive, beauty, architecture, and physical products.

For these categories:

- Primary hero and proof-bearing media SHOULD use high-fidelity contextual, photographic, editorial, or category-authentic visual treatment when imagery materially supports conversion.
- A low-detail generic SVG, abstract gradient, icon collage, or simplistic vector scene MUST NOT substitute for realistic proof-bearing media merely to satisfy the local-asset rule.
- If image generation is available and real business photography is not supplied, generate category-authentic visual media for atmosphere or storytelling, but MUST NOT present generated imagery as verified completed work, a real customer, or factual project evidence.
- If authentic business/project imagery is supplied, prefer it for portfolio, before/after, case-study, team, and trust sections; optimize and integrate it locally.
- Art direction MUST define subject, environment, composition, light, depth, crop, texture, color temperature, and responsive focal behavior rather than requesting a vague "modern business image."
- Visual fidelity should be consistent across the experience; one polished hero next to generic filler imagery fails the system.

The local-asset requirement is a delivery constraint, not permission to lower image quality.

---

# Local Directory Standard
<!-- id: assets.local-directory -->

Choose a project-native asset location.

Recommended static structure:

```text
assets/
  images/
    generated/
    content/
  illustrations/
  icons/
```

Recommended framework/public structure:

```text
public/
  assets/
    images/
      generated/
    illustrations/
    icons/
```

Use the framework's normal asset pipeline when it provides a better canonical location.

---

# File Naming Standard
<!-- id: assets.file-naming -->

Use descriptive stable filenames.

Good:

```text
dental-clinic-hero-patient.webp
logistics-control-room-hero.webp
fintech-mobile-dashboard.webp
property-search-map-background.webp
```

Avoid:

```text
image1.png
final-final.png
generated_003.png
temp.jpg
```

---

# Local Reference Standard
<!-- id: assets.local-reference -->

Generated code MUST reference the local asset through the project's normal relative or framework-native path.

Examples:

```html
<img src="/assets/images/generated/dental-clinic-hero.webp" ...>
```

```css
background-image: url("/assets/images/generated/brand-texture.webp");
```

Do not leave a generated asset disconnected from the files that use it.

---

# Asset Creation Workflow
<!-- id: assets.creation-workflow -->

For each required custom asset:

```text
Define Purpose
↓
Define Art Direction
↓
Define Required Aspect Ratio / Composition
↓
Generate
↓
Inspect
↓
Regenerate or Edit if Needed
↓
Save Locally
↓
Optimize
↓
Add Alt / Accessibility Treatment
↓
Reference in Implementation
↓
Render Final Page / Screen
↓
Inspect Crop and Performance
```

---

# Image Prompting Standard
<!-- id: assets.prompting -->

Asset-generation instructions SHOULD define:

- subject
- context/environment
- composition
- camera/viewpoint
- lighting
- palette
- mood
- realism/stylization
- negative space requirements
- target aspect ratio
- brand relationship
- exclusions when necessary

Avoid vague prompts such as:

```text
modern business image
```

---

# Composition-for-UI Standard
<!-- id: assets.composition-for-ui -->

Generate imagery for its actual placement.

If text overlays the left side, the subject SHOULD generally avoid occupying that same area.

Consider:

- text-safe negative space
- crop at desktop
- crop at mobile
- focal point
- responsive object positioning
- subject legibility
- contrast behind overlays

---

# Responsive Asset Standard
<!-- id: assets.responsive -->

Important assets SHOULD work across required viewports.

Where one crop cannot serve all layouts, create or derive separate crops.

Examples:

```text
hero-desktop.webp
hero-mobile.webp
```

Do not rely on destructive automatic cropping when the subject is important.

---

# Format Standard
<!-- id: assets.format -->

For web imagery, prefer efficient formats supported by the project and browser target.

Typical preference:

- AVIF where appropriate
- WebP
- optimized JPEG for photographic fallback where needed
- PNG when transparency or lossless output justifies it
- SVG for vector/procedural artwork when safe and appropriate

If the generation tool outputs PNG, convert to an optimized delivery format when the environment supports conversion and quality remains acceptable.

---

# Dimension Standard
<!-- id: assets.dimension -->

Do not ship needlessly oversized media.

Generate or resize assets to dimensions appropriate for their rendered use and high-density displays.

Preserve aspect ratio unless intentional art direction requires another crop.

---

# Compression Standard
<!-- id: assets.compression -->

Compress generated assets before production delivery when practical.

Optimization MUST NOT introduce obvious quality damage in prominent imagery.

---

# Explicit Dimensions Standard
<!-- id: assets.explicit-dimensions -->

Web implementations SHOULD define image dimensions or aspect ratio so layout space is reserved before the asset loads.

This reduces layout shift.

---

# Lazy Loading Standard
<!-- id: assets.lazy-loading -->

Below-the-fold imagery SHOULD generally use lazy loading.

Do not lazy-load the primary LCP hero image merely by habit.

Prioritize critical visual resources appropriately.

---

# Alt Text Standard
<!-- id: assets.alt-text -->

Meaningful images MUST receive appropriate text alternatives.

Alt text SHOULD describe the image's functional or informational purpose in context.

Decorative images SHOULD use the appropriate decorative treatment.

Do not stuff SEO keywords into alt text.

---

# Generated People Standard
<!-- id: assets.generated-people -->

When generated imagery includes people:

- avoid deceptive representation of real employees unless explicitly authorized
- do not label generated people as actual customers, clinicians, executives, or testimonials
- avoid fabricated identity claims
- maintain demographic and contextual appropriateness
- avoid stereotypical representation

Generated imagery MAY illustrate the service experience without claiming the depicted people are real customers or staff.

---

# Regulated / Trust-Critical Imagery Standard
<!-- id: assets.regulated-imagery -->

For healthcare, finance, legal, safety, government, and other trust-critical contexts:

- imagery MUST NOT imply unsupported credentials
- imagery MUST NOT depict unsafe professional practice
- imagery MUST NOT fabricate proof
- imagery SHOULD support credibility without pretending to document real outcomes

---

# Product Representation Standard
<!-- id: assets.product-representation -->

Do not generate fictional product screenshots and present them as actual implemented product functionality unless the user explicitly requested conceptual product imagery.

If the product is being implemented, prefer screenshots/renderings of the real implementation after it exists.

---

# Diagram Standard
<!-- id: assets.diagrams -->

When a diagram can explain structure more clearly than decorative imagery, prefer a diagram.

Diagrams SHOULD use:

- readable labels
- clear direction
- consistent symbols
- sufficient contrast
- meaningful grouping

Store diagram source locally when practical.

---

# Icon Asset Standard
<!-- id: assets.icons -->

Prefer an approved local/open icon system for common UI actions rather than generating each utility icon as an image.

Generate custom icons only when brand differentiation or specialized subject matter justifies them.

---

# Asset Manifest Standard
<!-- id: assets.asset-manifest -->

Substantial projects with multiple custom assets SHOULD maintain an asset record.

Recommended:

```text
assets/ASSET_MANIFEST.md
```

Each custom asset MAY record:

```text
Filename
Purpose
Used By
Aspect Ratio
Alt Text
Generation / Source Type
Notes
```

Do not include hidden chain-of-thought or proprietary prompt internals.

---

# Rights & Provenance Standard
<!-- id: assets.rights-provenance -->

Do not copy protected visual assets from competitors or unrelated websites into a generated project.

Use:

- AI-generated assets
- user-provided authorized assets
- appropriately licensed assets
- public-domain assets
- self-created local graphics

Record required attribution when a license requires it.

---

# External Asset Exception
<!-- id: assets.external-exception -->

External assets MAY be used only when:

- the user explicitly requests them
- a required licensed brand/vendor asset must remain externally sourced
- a map/tile/media service requires hosted delivery
- a technical integration requires a vendor-hosted asset

Document material external dependencies.

---

# Single-File Artifact Exception
<!-- id: assets.single-file-exception -->

If the user explicitly requests a single self-contained file, embedded assets MAY be used when technically appropriate.

Do not embed large base64 media into ordinary multi-file projects.

---

# Asset Failure Guard
<!-- id: assets.failure-guard -->

If image generation is required but the environment cannot generate images:

- do not silently insert remote placeholders
- use a local procedural/SVG/CSS alternative only when it legitimately satisfies the design
- otherwise identify the missing asset requirement clearly

When generation capability exists, this exception SHOULD NOT be used merely for convenience.

---

# Visual Asset QA Checklist
<!-- id: assets.qa-checklist -->

Before finalization:

- [ ] required custom assets exist locally
- [ ] implementation references valid local paths
- [ ] no placeholder URLs remain
- [ ] no broken images
- [ ] hero crop works on desktop
- [ ] hero crop works on mobile
- [ ] prominent imagery is visually coherent
- [ ] alt treatment is correct
- [ ] dimensions/aspect ratios reserve space
- [ ] heavy below-fold media is lazy-loaded where appropriate
- [ ] primary LCP imagery is prioritized appropriately
- [ ] assets are compressed/optimized
- [ ] no generated person is falsely represented as a real customer/staff member
- [ ] no fabricated visual proof exists
- [ ] licenses/attributions are handled when applicable

---

# Final Asset Standard
<!-- id: assets.final-standard -->

If the design needs imagery to feel complete, create the imagery.

If the imagery is created, integrate it.

If it is integrated, optimize and validate it.

Production output SHOULD NOT delegate obvious visual completion work to an unspecified future step.
