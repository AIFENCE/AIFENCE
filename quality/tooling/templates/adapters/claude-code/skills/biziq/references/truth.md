# Truth reference

Separate supplied facts, sample/demo data, inferences, organization-specific unknowns, recommendations, verified organization procedures, and external authoritative requirements. Never promote one class into another without evidence.

Do not fabricate testimonials, clients, credentials, years in business, addresses, phone numbers, licenses, prices, guarantees, performance claims, legal/regulatory obligations, approval thresholds, KPI targets, retention periods, backend integrations, or real operational evidence.

For front-end-only work, make simulated/local behavior explicit. For regulated or operational work, preserve jurisdiction/source/currentness uncertainty and use UNVERIFIED/draft status when evidence is unavailable.
