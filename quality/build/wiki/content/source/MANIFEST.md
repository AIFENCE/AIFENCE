# Operations 2.0 Procedure Resolution
<!-- id: manifest.operations-2-resolution -->

For job-title lookup or profile context, use `JOBS.md` and the exact `operations/<profile>.md` shard as before. For a material operating procedure, role specification, runbook, work instruction, KPI system, or authority matrix, **do not stop at the profile SOP section**.

Resolve in this order:

```text
MANIFEST / PROFILE_MATRIX
→ exact JOBS role + operations profile section
→ OPERATIONAL_PROCEDURE_COMPILER.md
→ PROCEDURE_AUTHORITY.md (when authority/accuracy matters)
→ DECISION_RIGHTS.md (for consequential decisions/approvals)
→ OPERATIONAL_EVIDENCE.md (for evidence/handoff/definition of done)
→ KPI_GOVERNANCE.md (when metrics are material)
→ active Domain 31 Evidence Gates
```

The stable `sop.*` address identifies baseline operating context. It does not certify that the text is organization-approved or externally authoritative.

# Stable ID Construction
<!-- id: manifest.id-construction -->

For canonical industry slug `{industry-slug}`:

```text
INDUSTRIES.md → industry.{industry-slug}
PROFILE_MATRIX.md → row keyed by industry.{industry-slug}
FEATURES.md → features.industry.{industry-slug}
DESIGN.md → design.industry.{industry-slug}
HALO.md → halo.industry.{industry-slug}
JOBS.md → jobs.industry.{industry-slug}
operations/<profile>.md → sop.{industry-slug}.{role-slug}
```

SOP role slugs are resolved from `JOBS.md` / the corresponding operations shard. Do not invent an SOP address when a role is absent.
